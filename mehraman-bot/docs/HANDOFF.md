# سند انتقال: بازوی بله‌ی مهرمان (برای ادامه‌ی کار توسط هر هوش مصنوعی)

## این پروژه چیست
بازوی بله‌ی «@Mehremanbot» برای مجموعه‌ی تخصصی خانواده «مهرمان». هدف: (۱) پاسخ به پرسش مخاطبان فقط بر پایه‌ی «محتوای پشتیبان» مهرمان بدون آشکارکردن چارچوب دینی/نظری؛ (۲) پشتیبانی دوره (کاربرگ، تمرین، یادآوری، چک‌این)؛ (۳) پروفایل/نقشه‌ی رشد ساده؛ (۴) ارجاع به مشاور. **این پروژه جزو پروژه‌های صاحب سرور نیست؛ فقط روی سرور او اجرا می‌شود.** مالک محتوا: مهرمان.

## مخاطب و برند
زوج‌های متأهل ۲۵ تا ۴۵ ساله، تحصیل‌کرده، کاربران بله. هویت «خانه»: ایستگاه‌ها با نام عناصر خانه (آستانه خانه، چراغ تشخیص، راهروی بن‌بست، پنجره شنیدن، …). رنگ‌ها: زیتونی #243C17، کرم #F8EFDF، نسکافه‌ای #D3AD84. لحن: محاوره‌ای، صمیمی، امیدبخش، توانمندساز، بدون نصیحت از بالا (نمونه در `content/persona.md`). کانال: @mehreman_khanevadeh ، ادمین: @admin_mehreman.

## معماری
پایتون ۳.۱۲، فقط `httpx` و `PyYAML`؛ long‑polling روی API بله (`https://tapi.bale.ai/bot<TOKEN>/…`).

| فایل | نقش |
|---|---|
| `mehraman_bot/main.py` | حلقه‌ی اصلی، `--check` |
| `bale.py` | کلاینت بله، کیبورد، شکستن پیام بلند |
| `handlers.py` | منو، پروفایل، تمرین، چک‌این، پرسش‌وپاسخ، ارجاع |
| `admin_panel.py` | پنل مدیریت دکمه‌ای (افزودن محتوا/کاربرگ، حذف، گزارش) |
| `knowledge.py` | بارگذاری محتوا + بازیابی BM25 فارسی |
| `persona.py` | پرامپت سیستمی + قواعد ثابت ایمنی (`CORE_RULES`) |
| `llm.py` | Anthropic / Gemini / OpenAI‑compatible با یک رابط |
| `safety.py` | تشخیص اضطراری/ارجاع بدون مدل (`content/safety.yaml`) |
| `db.py` | SQLite: کاربر، پیشرفت، تاریخچه، ارجاع، پرسش‌های بی‌پاسخ |
| `content.py` | دوره‌ها/کاربرگ‌ها/پیام‌ها + اعتبارسنجی |
| `ingest.py` | docx/pdf ← Markdown |
| `scheduler.py` | یادآوری روزانه |

داده‌ی ماندگار: `data/` (SQLite)، `knowledge/`، `content/`. هیچ اسراری در کد نیست؛ همه از `.env`.

## جریان پاسخ به پرسش
`safety.check` (اضطراری ← پاسخ ثابت) ← سقف روزانه ← بازیابی ۵ تکه ← اگر امتیاز ضعیف: «خارج از دامنه» + ثبت در `unanswered` ← فراخوانی مدل با `persona + CORE_RULES + مواد مرجع` ← حذف `[[REFER]]` و افزودن دکمه‌ی مشاور.

## ارتقا بدون برنامه‌نویس
`docs/UPDATING_WITH_AI.md`. ادمین با «🛠 پنل مدیریت» محتوا/کاربرگ اضافه می‌کند. تغییر لحن: `content/persona.md`. تغییر مدل: `.env`.

## اجرا
`cp .env.example .env` ← پر کردن ← `python -m mehraman_bot.main --check` ← `python -m mehraman_bot.main`. تست: `pip install -r requirements-dev.txt && pytest` (۲۲ تست). کانتینر: `Dockerfile`, `docker-compose.yml`. نکته‌ی میکروتیک: ایمیج باید برای معماری روتر ساخته شود.

## تصمیم‌های طراحی که باید حفظ شوند
- بازو **رابط** است؛ منطق/داده قفل بازو نشود (وب‌اپ بعدی همان محتوا/DB را می‌خواند).
- محتوای پشتیبان داخلی است: نقل مستقیم/ارجاع به منبع/بیان صریح چارچوب دینی ممنوع.
- «گلوگاه» فرضیه است نه برچسب؛ بازو تشخیص بالینی نمی‌دهد؛ مشکل ساختاری به مهارت فردی تقلیل داده نشود.
- اطلاعات حساس در متن آزاد جمع نشود (فرم ارجاع حداقلی است).
- تحلیل گلوگاه/فرضیه‌سازی کامل عمداً **پیاده نشده**: منتظر نسخه‌ی مبنای «الگوی توسعه وجودی» و «الگوی خانواده».
- قیمت‌ها در کد/مدل ثابت نشوند (`content/faq.yaml`).

## کارهای باز
محتوای پشتیبان واقعی و کاربرگ‌ها اضافه نشده‌اند؛ شماره‌های اضطراری `safety.yaml` باید تطبیق داده شود؛ تست زنده با بله/مدل انجام نشده؛ ایمیج Docker هنوز ساخته/آزموده نشده.
