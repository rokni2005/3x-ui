# استقرار روی سرور

این اسکریپت‌ها برای نصب/به‌روزرسانی ربات روی یک سرور لینوکسی (دبیان/اوبونتو) هستند.
اگر سشن Claude Code شما به سرور مقصد دسترسی SSH واقعی دارد، خودش می‌تواند این دستورات
را اجرا کند؛ در غیر این صورت باید توسط خودتان روی سرور اجرا شوند.

## نصب اولیه

روی سرور، به‌عنوان root:

```bash
curl -fsSL https://raw.githubusercontent.com/rokni2005/3x-ui/claude/bale-fruit-order-bot-w2lyzu/balebot/deploy/setup.sh -o setup.sh
chmod +x setup.sh
./setup.sh
```

(یا اگر ریپازیتوری را از قبل کلون کرده‌اید: `balebot/deploy/setup.sh` را مستقیم اجرا کنید.)

> اگر دانلود مستقیم `go.dev`/`proxy.golang.org` از روی سرور شما (مثلاً به‌دلیل
> تحریم/فیلترینگ) با خطای ۴۰۴/۴۰۳ مواجه شد، Go را از یک میرور جایگزین (مثلاً
> `mirrors.aliyun.com/golang`) نصب کنید و `go env -w GOPROXY=https://goproxy.cn,direct`
> بزنید، بعد دوباره `setup.sh` را اجرا کنید.

اسکریپت به‌صورت خودکار:
- در صورت نبود، Go را نصب می‌کند (بدون نیاز به gcc/CGO).
- یک کاربر سیستمی `balebot` می‌سازد.
- سورس را در `/opt/balebot/src` کلون/آپدیت و در `/opt/balebot/bin/balebot` می‌سازد.
- فایل تنظیمات را در `/etc/balebot/balebot.env` (از روی `balebot.env.example`) می‌سازد —
  **این فایل را باز کنید و مقادیر واقعی (توکن ربات، رمز ادمین و ...) را وارد کنید.**
- سرویس systemd را نصب می‌کند (بدون روشن کردن، چون هنوز تنظیمات کامل نیست).

بعد از پر کردن `/etc/balebot/balebot.env`:

```bash
systemctl enable --now balebot
journalctl -u balebot -f
```

## به‌روزرسانی بعدی

هر وقت کد تغییر کرد، فقط دوباره همان اسکریپت را اجرا کنید؛ چون `balebot.env` از قبل
وجود دارد، این‌بار فقط کد را آپدیت، دوباره build و سرویس را ری‌استارت می‌کند (تنظیمات
شما دست‌نخورده می‌ماند):

```bash
/opt/balebot/src/balebot/deploy/setup.sh
```

## دسترسی به پنل ادمین

پنل ادمین فقط روی `127.0.0.1:8080` خود سرور گوش می‌دهد (`ADMIN_LISTEN_ADDR` در
`/etc/balebot/balebot.env`). دو راه برای دسترسی:

**۱. SSH tunnel (بدون نیاز به دامنه):**

```bash
ssh -L 8080:127.0.0.1:8080 <user>@<server-ip>
```

و سپس در مرورگر: `http://127.0.0.1:8080/fruits`

**۲. دامنه‌ی عمومی با HTTPS (برای استفاده‌ی روزمره از گوشی):**

یک ساب‌دامنه را به IP سرور اشاره بدهید، بعد یک reverse proxy (nginx یا Caddy) با گواهی
Let's Encrypt جلوی همان `127.0.0.1:8080` بگذارید (پورت خود ربات را عوض نکنید — فقط
پراکسی از بیرون در دسترس باشد). حتماً یک rate-limit روی همان مسیر بگذارید، چون تنها
لایه‌ی احراز هویت پنل، HTTP Basic Auth است. قبل از اضافه‌کردن دامنه، حتماً چک کنید که
آن ساب‌دامنه از قبل به سرویس دیگری در همان سرور اشاره نداشته باشد (`nginx -T` یا
`ls /etc/nginx/sites-enabled/`), وگرنه سرویس قبلی از دسترس خارج می‌شود.
