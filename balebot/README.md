# ربات سفارش آنلاین میوه (بله)

یک ربات مستقل برای پیام‌رسان **بله** که به مشتری‌ها امکان می‌دهد میوه سفارش بدهند:
انتخاب میوه از لیست (همراه با عکس، در صورت آپلود)، تعیین وزن، مشاهده سبد خرید، ثبت
آدرس و شماره تماس، مشاهده فاکتور و پرداخت ودیعه. قیمت‌ها، حداقل وزن قابل سفارش و عکس
هر میوه، و سفارش‌های ثبت‌شده، در یک پایگاه داده SQLite ذخیره می‌شوند و از یک پنل ادمین
تحت وب قابل مدیریت‌اند. تمام تعامل‌ها — هم برای مشتری و هم برای ادمین — با دکمه انجام
می‌شود، نه با تایپ دستور.

این پروژه کاملاً مستقل از پنل ۳X-UI است (ماژول Go جداگانه، بدون دست‌زدن به کد پنل یا
ربات تلگرام ادمین موجود) و صرفاً درون همین ریپازیتوری نگه‌داری می‌شود. تنها وابستگی
بیرونی، درایور Go خالص SQLite (`modernc.org/sqlite`) است که نیازی به gcc/CGO ندارد —
یعنی روی سرور فقط باینری کامپایل‌شده کافیست، بدون نیاز به نصب توول‌چین Go.

## سناریوی گفتگو در ربات (مشتری)

1. اولین ورود (یا زدن دکمه پایین صفحه) → نمایش لیست میوه‌ها به صورت دکمه‌های شیشه‌ای.
2. با زدن روی یک میوه، عکس آن میوه (در صورت وجود)، قیمت هر کیلو، حداقل وزن قابل سفارش
   و یک انتخاب‌گر وزن (➖ / ➕ با گام ۰.۵ کیلوگرم، از حداقل وزن همان میوه شروع می‌شود)
   نشان داده می‌شود؛ با زدن «افزودن به سبد خرید» آن قلم به سبد اضافه می‌شود.
3. کاربر می‌تواند چند میوه مختلف اضافه کند و در نهایت روی «مشاهده سبد خرید و ثبت سفارش»
   بزند.
4. سپس آدرس کامل و شماره تماس به صورت پیام متنی از کاربر گرفته می‌شود.
5. فاکتور نهایی نمایش داده می‌شود: ریز اقلام، جمع کل، یادآوری «ارسال ما رایگانه»،
   مبلغ ثابت ودیعه (پیش‌فرض ۲۰۰,۰۰۰ تومان) و مابقی مبلغ که پس از تحویل سفارش دریافت
   می‌شود.
6. با زدن دکمه پرداخت ودیعه:
   - اگر `PAYMENT_PROVIDER_TOKEN` تنظیم شده باشد، یک فاکتور پرداخت آنلاین (کیف پول بله)
     باز می‌شود و مبلغ مستقیماً از طریق بله کسر می‌شود.
   - در غیر این صورت، شماره کارت برای واریز کارت‌به‌کارت نمایش داده می‌شود و کاربر
     تصویر رسید را ارسال می‌کند.
   در هر دو حالت، سفارش در پایگاه داده ثبت نهایی می‌شود و خلاصه سفارش برای چت مدیر
   ارسال می‌شود.

هیچ‌جای این مسیر نیازی به تایپ دستور نیست: حتی به‌جای `/start`، یک دکمه ثابت پایین
صفحه («🍉 منو و سفارش میوه») همیشه در دسترس مشتری است.

## پرداخت آنلاین (کیف پول بله)

⚠️ **این بخش بر پایه‌ی الگوی متداول Telegram Bot Payments API پیاده شده، چون مستندات
دقیق درگاه پرداخت بله (`dev.bale.ai`) از محیط توسعه در دسترس نبود.** قبل از اعتماد
کامل به آن برای مشتری‌های واقعی، حتماً با یک تراکنش واقعیِ کوچک (مثلاً ۱۰,۰۰۰ تومان
به‌جای مبلغ واقعی ودیعه، از طریق `DEPOSIT_AMOUNT` موقت) تست کنید:

1. `PAYMENT_PROVIDER_TOKEN` را با توکن کیف‌پول (مثل `WALLET-...`) پر کنید.
2. یک‌بار با `DEBUG_UPDATES=1` ربات را اجرا کنید تا بدنه خام پاسخ‌های Bale (از جمله
   ساختار دقیق `pre_checkout_query` و `successful_payment`) در لاگ چاپ شود.
3. یک سفارش تستی کامل کنید و لاگ را بررسی کنید که آیا نام فیلدهایی مثل `total_amount`،
   `invoice_payload` و `currency` با چیزی که کد انتظار دارد (در `bale/types.go`) مطابقت
   دارد یا نه؛ در صورت اختلاف، فقط کافیست تعریف `struct` مربوطه اصلاح شود.
4. `PAYMENT_AMOUNT_MULTIPLIER` (پیش‌فرض `10`) فرض می‌کند مبلغ داخلی بر حسب تومان است و
   باید برای درگاه به ریال (کوچک‌ترین واحد پول) تبدیل شود؛ اگر تراکنش تستی مبلغ
   اشتباهی نشان داد، همین مقدار را اصلاح کنید — نیازی به تغییر کد نیست.
5. بعد از اطمینان، `DEBUG_UPDATES` را خاموش کنید.

تا وقتی `PAYMENT_PROVIDER_TOKEN` خالی باشد، ربات همان روال امن و ساده‌ی واریز
کارت‌به‌کارت + ارسال رسید را استفاده می‌کند — یعنی راه‌اندازی اولیه هیچ وابستگی به این
تایید ندارد.

## پنل ادمین (وب)

با تنظیم `ADMIN_USERNAME` و `ADMIN_PASSWORD`، یک پنل وب ساده (با Basic Auth) روی
`ADMIN_LISTEN_ADDR` (پیش‌فرض `127.0.0.1:8080`، یعنی **فقط قابل دسترسی از خود سرور**)
بالا می‌آید:

- **`/fruits`** — لیست همه میوه‌ها با امکان ویرایش «قیمت هر کیلو»، «حداقل وزن قابل
  سفارش» و آپلود «عکس» برای هرکدام (jpg/png/webp)؛ تغییرات بلافاصله در پایگاه داده
  ذخیره و در ربات اعمال می‌شود (بدون نیاز به ری‌استارت ربات).
- **`/orders`** — فهرست سفارش‌های ثبت‌شده (اقلام، جمع کل، ودیعه، آدرس، شماره تماس).
- در بات خود ادمین (چتی که `ADMIN_CHAT_ID` را دارد) هم یک دکمه ثابت «📦 سفارش‌های
  اخیر» وجود دارد تا بدون باز کردن پنل وب هم بشود آخرین سفارش‌ها را دید.

اگر `ADMIN_USERNAME`/`ADMIN_PASSWORD` تنظیم نشوند، پنل ادمین اصلاً اجرا نمی‌شود.
چون پنل فقط روی `127.0.0.1` گوش می‌دهد، دسترسی به آن از بیرون فقط با SSH tunnel ممکن
است، مثلاً:

```bash
ssh -L 8080:127.0.0.1:8080 user@your-server
# سپس در مرورگر خودتان: http://127.0.0.1:8080/fruits
```

این یعنی نیازی به دامنه یا گواهی HTTPS برای پنل ادمین نیست و رمز عبور هرگز روی
اینترنت عمومی رد و بدل نمی‌شود.

## ساخت و اجرا

```bash
cd balebot
go build -o balebot .
```

متغیرهای محیطی:

| متغیر | الزامی | توضیح |
|---|---|---|
| `BALE_BOT_TOKEN` | بله | توکن ربات، از طریق ربات «BotFather» در بله ساخته می‌شود. |
| `DB_PATH` | خیر | مسیر فایل پایگاه داده SQLite (پیش‌فرض `balebot.db`). |
| `PHOTOS_DIR` | خیر | پوشه ذخیره عکس میوه‌های آپلودشده (پیش‌فرض `photos`). |
| `ADMIN_CHAT_ID` | خیر | شناسه چت مدیر/فروشنده برای دریافت خودکار سفارش‌های جدید و رسید. |
| `DEPOSIT_AMOUNT` | خیر | مبلغ ودیعه به تومان (پیش‌فرض `200000`). |
| `DEPOSIT_CARD_NUMBER` | خیر | شماره کارت مقصد واریز ودیعه (روش پرداخت پیش‌فرض). |
| `DEPOSIT_CARD_HOLDER` | خیر | نام صاحب کارت. |
| `PAYMENT_PROVIDER_TOKEN` | خیر | توکن کیف‌پول بله برای پرداخت آنلاین (بخش «پرداخت آنلاین» بالا را ببینید). |
| `PAYMENT_CURRENCY` | خیر | کد ارز فاکتور پرداخت (پیش‌فرض `IRR`). |
| `PAYMENT_AMOUNT_MULTIPLIER` | خیر | ضریب تبدیل تومان به کوچک‌ترین واحد پول درگاه (پیش‌فرض `10`). |
| `DEBUG_UPDATES` | خیر | با `1`، بدنه خام پاسخ‌های API بله در لاگ چاپ می‌شود (برای عیب‌یابی پرداخت). |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | خیر (اما برای فعال شدن پنل ادمین هر دو لازم‌اند) | ورود به پنل مدیریت. |
| `ADMIN_LISTEN_ADDR` | خیر | آدرس/پورت پنل ادمین (پیش‌فرض `127.0.0.1:8080`). |

اجرا:

```bash
BALE_BOT_TOKEN="..." \
DB_PATH="/var/lib/balebot/balebot.db" \
PHOTOS_DIR="/var/lib/balebot/photos" \
ADMIN_CHAT_ID="123456789" \
DEPOSIT_CARD_NUMBER="6037-xxxx-xxxx-xxxx" \
DEPOSIT_CARD_HOLDER="نام و نام خانوادگی" \
ADMIN_USERNAME="admin" \
ADMIN_PASSWORD="یک-رمز-قوی" \
./balebot
```

ربات با استفاده از long polling (`getUpdates`) اجرا می‌شود و نیازی به وب‌هوک یا دامنه
عمومی ندارد. روی سرور، بهتر است آن را به‌صورت یک سرویس systemd اجرا کنید تا با ری‌استارت
سرور خودش هم بالا بیاید.

## داده اولیه و مدل داده

هنگام اولین اجرا (وقتی پایگاه داده خالی باشد)، لیست ۱۹ میوه اولیه با قیمت‌های داده‌شده
به‌صورت خودکار در جدول `fruits` درج می‌شود (`db/seed.go`، بدون عکس). این مقادیر فقط
پیش‌فرض اولیه هستند و بعد از آن، **قیمت، حداقل وزن و عکس هر میوه باید از پنل ادمین
(`/fruits`) تغییر داده شود**، نه از کد.

جدول `orders` هم هر سفارش نهایی‌شده (بعد از دریافت رسید یا پرداخت آنلاین) را با ریز
اقلام، جمع کل، ودیعه، آدرس و شماره تماس نگه می‌دارد.
